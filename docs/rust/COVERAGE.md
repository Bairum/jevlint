# Rust research coverage ledger

This ledger accounts for the **71 semantic candidates** (26 memory/resource, 27 API, 18 concurrency/I/O) and the substantive findings in the tooling report. Accounting is not automation: a retained research finding may be narrowly implemented, native-tool-owned, generic-but-uncalibrated, deferred, or intentionally excluded.

Full source snapshots, including exact primary-source URLs, exceptions, and version caveats: [memory/resources](research/memory.md), [API/functions/errors](research/api.md), [concurrency/async/I/O](research/concurrency.md), [tooling](research/tooling.md). Each source-linked candidate below identifies its exact report section by stable candidate ID. Tooling rows identify the original numbered section and subsection/topic. This ledger does not replace those reports. The [root synthesis](../../RUST-PACK-RESEARCH.md) supplies the three-layer rationale.

## Approved layers and status vocabulary

The first-class primary Rust suite lives in `packs/rust-*`, separate from the
database-joins tutorial under `examples/packs/`. `rust-core` is the strict base;
`rust-core-advisory` and the four specialist packs are deliberate opt-ins.
Pack IDs remain `Bairum/rust-*`. Fixture calibration is now measured, but no
pack is automatically enabled or promoted to blocking enforcement.

| Layer/status | Meaning and implementation contract |
| --- | --- |
| **L1 / native guidance** | Native compiler/formatter/lint/test/doc baseline: [`scripts/check-rust.sh`](../../scripts/check-rust.sh) and [`TOOLING.md`](TOOLING.md). The script's approved scope is fmt/check/test/doc/default Clippy; project-specific matrices, separate builds, optional lints/tools, and publishing checks are guidance unless explicitly exercised. |
| **L2 / P** | Strict core **pack implemented; fixture calibration measured**: [rust-core manifest](../../packs/rust-core/pack.json). P means a delivered pack artifact, not automatic activation or default-enforcement readiness. Real-project precision is unmeasured. |
| **L3 / P** | Opt-in advisory and specialist **packs implemented; fixture calibration measured**: [rust-core-advisory](../../packs/rust-core-advisory/pack.json), [rust-tokio](../../packs/rust-tokio/pack.json), [rust-api](../../packs/rust-api/pack.json), [rust-unsafe](../../packs/rust-unsafe/pack.json), [rust-performance](../../packs/rust-performance/pack.json), [rust-readability](../../packs/rust-readability/pack.json). |
| **Generic / U** | Existing rule definition in [`jevlint.json`](../../jevlint.json), but **uncalibrated for this Rust finding**. A generic rule's presence is not evidence of equivalent Rust coverage. |
| **Deferred / D** | No approved dedicated rule for the identified semantic residual; linked F item states the missing evidence and promotion trigger. |
| **Excluded / X** | Intentional policy decision, not forgotten backlog. Reconsider only with an explicit project contract, not because a construct occurs. |

`Core`, `Advisory`, `Tokio`, `API`, `Unsafe`, `Perf` and `Readability` name the corresponding manifests above. There are **35 implemented rule IDs across 7 packs**: Core 10, Advisory 6, Tokio 7, API 3, Unsafe 4, Perf 2, Readability 3. The suite has **461 evaluation cases**: Core 140, Advisory 68, Tokio 98, API 35, Unsafe 68, Perf 29, Readability 23 (the original suite had 426; Readability also ships two compile-only repair fixtures). Every rule in the six correctness packs has violation, passing-neighbor and legitimate-exception coverage; Readability rules have violation/repair twins and exception cases. Additional cases cover important boundaries. Compilation and structural checks do not establish model precision. See [CALIBRATION.md](CALIBRATION.md), [F01](#f01) and [verification status](#verification-and-status).

Rust rule selection uses `include: ["**/*.rs"]`, not a nonexistent `rule.languages` field. `sourceMatch` is an OR of RE2 patterns over the primary unit's source: a cheap subject prefilter, not semantic evidence or a search of attached context. Test units are structurally skipped by default; a project may explicitly set `includeTests: true`. Pack manifests load shared `guidance.md` once rather than repeating common evidence requirements in each rule.

`context.types` now opts into bounded type/impl context for **type units, Self-only methods and concrete type references**. Same-file declarations and matching impls are available; cross-file impls are candidates when a type name has one project-wide definition among discovered sources. Ambiguous names stay same-file. Rule-excluded declaration paths are filtered before the additional-context caps of 12 declarations and 16 KiB. API15/API16 use type-primary judgments with these matching impls. This is syntactic source context, not Rust module/name resolution, compiler typing or macro expansion; incomplete required comparisons still call for abstention.

The advisory tier infers review-worthy recovery, error-preservation, retained application-state mutation, input-bound, exclusive-create and buffered-completion conventions without the strict tier's explicit application-contract requirement. Its six informational rules are human-review prompts, not proof of a documented promise being broken. The mutation advisory requires concrete retained-state observation; mutable scratch/output buffers and temporary leases do not imply transactions. Unsafe coverage additionally includes `rust-unsafe-ffi-pointer-contract` (visible foreign pointer, extent, lifetime and release obligations) and `rust-unsafe-pyo3-reference-ownership` (CPython/PyO3 new, borrowed and stolen references, owner release and unchecked casts). Missing foreign contracts are not invented violations.

Semantic findings require the applicable contract, reachable counterexample and relevant exceptions; API identity must be visible when the conclusion depends on a library contract. Current extraction lacks compiler typing, name resolution, macro expansion, complete cross-file call/ownership graphs and exported reachability. Missing type/macro/caller/docs context is **not evidence that checks, supervision, bounds, documentation, or cleanup are absent**. See [F02](#f02). Unsafe rules require concrete counterexamples; unresolved obligations remain manual/deferred, never global soundness claims.

## Intentional exclusion policies

These are durable decisions, not F backlog. The complete exclusions remain in [memory § “What NOT to include in the semantic pack”](research/memory.md), [API § “Preferences to exclude as universal rules”](research/api.md), [concurrency § “Reject or defer as universal pack rules”](research/concurrency.md), and tooling §§1, 2, 4, 6.

| Decision | Intentionally excluded | Reconsideration boundary |
| --- | --- | --- |
| X01 — Native ownership | Model copies of compiler borrow/type/Send/Sync/dyn errors, rustfmt layout, naming, doc-heading presence and stock Clippy patterns | Only a demonstrated contextual residual earns semantic review; disabled optional lint alone is insufficient. |
| X02 — No construct bans | Universal bans on clone/allocation/Box/Arc/Rc/RefCell/Mutex/unsafe/raw pointers/traits/dyn/unwrap/expect/panic/forget/ManuallyDrop/explicit lifetimes | An explicit reachable contract violation, not construct occurrence; preserve tests, invariants, resource owners and intentional sharing/leaks. |
| X03 — No numerical Rust law | Universal function/parameter/nesting/clone counts, allocation sizes, lock duration, task/queue capacity, timeout or yield cadence | Explicit project budget/contract plus evidence; native configurable heuristics remain policy. |
| X04 — No forced API architecture | Mandatory newtypes/typestate/builders, traits for every dependency or multiple implementations, main/lib/facade/module layout, generics/dyn preference, all-private/non_exhaustive/sealed/common-traits everywhere | Actual domain misuse, extension/stability/caller or construction requirement. Existing public commitments must be reviewed before change. |
| X05 — No prescribed crates/error representation | Mandatory anyhow/thiserror/serde/bitflags or typed/dyn/heap errors, universal Send+Sync+'static/no_std | Existing dependency/environment/MSRV and real consumer/error requirements determine implementation. Stale anti-context or authors-field claims are rejected. |
| X06 — No universal runtime migration | Always Tokio mutex/message passing/RwLock/atomics, never guard across await, every spawn immediately joined, mandatory TaskTracker/JoinSet/CancellationToken | Actual runtime/type/progress/lifecycle contract; adequate existing owners and legitimate async guards stay valid. |
| X07 — No fake scheduling/atomic guarantees | Await/yield guarantees other-task progress; all atomics SeqCst/Relaxed always wrong; static proof of arbitrary race/deadlock/starvation/cancellation freedom | Concrete protocol trace and appropriate evidence only; independent counters and intentional priority valid. |
| X08 — Completion is not durability | Flush every write/fsync every file/zeroize every buffer/custom Drop everywhere; create_new solves all path attacks | Actual completion/durability/erasure/path/cleanup promise; distinguish buffering, persistence, replacement and confinement. |
| X09 — No safety certificates | SAFETY comment, compiling safe wrapper, green Clippy/Miri/sanitizer/Loom/provider result as universal soundness; frozen alias model; stale historical/nightly contracts imposed everywhere | Exact version-appropriate operation contract and counterexample scope; unsupported tools/missing context are limitations, not bugs or proof. |
| X10 — No automatic maximal CI | Blanket pedantic/restriction/nursery, forbid(warnings), all-features/all-platform tools, mandatory Miri/fuzz/Loom on ordinary safe helpers | Explicit applicable project risk/support/policy and runnable environment; keep optional tools optional. |
| X11 — No testing ideology | Fixed coverage %, framework/one-test-per-function, mandatory private/public-only tests or runnable duplicate example for every item; ban ignore/no_run/compile_fail | Test/example's actual advertised promise and execution environment. |
| X12 — No mistaken failure classes | Business inconsistency/leaks universally called UB; non-unwind Rust panic always UB; catch_unwind catches abort/arbitrary foreign exceptions; blanket C-unwind edit | Distinguish logic/resource/safety/abort and establish real foreign/panic contract. |

## Mapping overlaps and feasibility risks

- M01/API08/API11 share ownership/caller-control concerns; native checks own mechanical cases. M10/API26 share `rust-perf-repeated-materialization`, limited to workload-proven repeated work, not every API intermediate-result suggestion.
- M04/C07/API27 share buffered completion; M05/API27 share fallible Drop. A single lost-output/root-cleanup defect must not become multiple diagnostics. Blocking teardown and crash durability remain separate explicit gaps.
- M09/C06 share untrusted buffering; C05 addresses admission/resource lifetime. A pipeline's one missing bound is one root finding; independent unbounded bytes versus tasks may justify separate findings only with distinct evidence.
- C02/M03 are only partially covered by C11's lock-dependency rule. Async guards intentionally crossing await remain valid; general retention, reentrancy and global lock order are not implied coverage.
- M12/M15/M17/M18 share local unsafe precondition review. M13/M14 share local panic invalidation, but **M14's forgotten-guard/leak and arbitrary trait-law dependence are not all unwind cases**. Initialization violated because of panic belongs to unwind root, not duplicate initialization findings.
- API14's invariant-bypassing DerefMut belongs to Core validation-bypass. The API Deref rule owns surprising/nontransparent behavior; API15's approved semantic residual is manual Eq/Hash, not all common-trait availability/laws.
- C03/C04/C07/C08/C10/C17 can describe one lifecycle failure; select the operative progress/owner/completion/shutdown/blocking root. C12/C13/C14/C15/C16/C17 do not silently become fully covered by adjacent Tokio IDs.
- Existing `swallowed-errors`, `accurate-doc-comments`, domain-state and function-structure rules can overlap approved/residual topics. Definitions are observed, Rust equivalence/calibration is not. Avoid duplicate enabled reports and honor configuration/pack overlay behavior.
- Macro-heavy Tokio evidence, generic/type resolution, attributed docs and cross-file supervisors/invariants may be missing from extracted requests. Qualified call spelling is not callee resolution; confidence cannot repair missing facts. Unsafe fixtures must never be executed as ordinary UB-producing tests. Cargo/tool/runtime versions and compilable versus intentionally illustrative fixture environments require explicit reconciliation.

## Verification and status

All **426** isolated Rust 2021 fixture targets across the six packs compiled
successfully. Faulty/unsafe/deadlocking fixtures were **not executed**.
Per-pack inventory: Core **138**, Advisory **64**, Tokio **98**, API **35**,
Unsafe **62**, Performance **29**.

The leak-free baseline ran
`python3 scripts/check-rust-packs.py --eval --repeat 3` with a real provider at
the global **0.8** floor: **426 cases**, **1278 case-runs**, with opaque fixture
names reaching the evaluator. Case-level majority under eval semantics
(below-floor fail = inconclusive) measured **recall 71/162** and
**specificity 229/264**. The flip rate was **0.054 / 5.4% (23 cases)**;
there were **4 abstain decisions** and **264 below-floor fail decisions**.
These majority aggregates differ from the per-run reporting metrics in the
[complete rule table and method](CALIBRATION.md).

The global floor stays **0.8**, and no pack rule sets `minFailProbability`.
Recommended consuming-project overrides improve fixture recall for some
rules; a rule floor replaces and overrides the global floor, not a maximum
with it. Those recorded floors were fitted on the old choice-confidence metric and pack calibration will refit them; the field name is `minFailProbability`. The overrides were fitted on these same fixtures, which double as
the calibration set. Only three runs were measured; **real-project precision
is still unmeasured**. The earlier **42/42** result was inflated by fixture
comments and verdict-bearing file names reaching the model, so it is not
leak-free accuracy evidence. See [CALIBRATION.md](CALIBRATION.md) for
reproduction, override configuration and all caveats.

Even at recommended overrides, Tokio cancellation-progress (**0.17**),
required-task-ownership (**0.07**) and lock-dependency (**0.33**), Unsafe
precondition-contract (**0.20**) and unwind-state (**0.07**), and Core
shared-clone-isolation (**0.27**) remain **not yet useful** because recall
is low. At 0.8, Core exclusive-create-race (**0.71**), conversion-contract
(**0.83**), unbounded-input-buffering (**0.88**), expected-failure-panics
(**0.89**), error-cause-loss (**0.89**) and shared-clone-isolation (**0.88**),

specificity is below 0.90.

## Rust readability: upstream generic rule accounting

`Bairum/rust-readability` is a separate opt-in review layer, not an extension
of the strict semantic tier. The upstream inventory below is
`upstream/master:jevlint.json` (26 rules). Rust ports use
`rust-readability-` IDs; native ownership is not an instruction to enable all
optional Clippy groups. See [calibration and project audit](CALIBRATION.md#rust-readability).

Project measurements below use a held-out private Rust workspace (43 files,
958 units). Its triage shaped candidate selection and rule exceptions, so
these are **tuning-set/in-sample measurements**, not held-out accuracy.

The shipped prefilters retain cost-control without turning token matches into
findings. Literal policy selects numeric-literal candidates; two literal-free
enum/constant repair twins are compile-only. Rustdoc selects attached line,
block and attribute documentation; **undocumented units are skipped**, not
explicit model pass judgments. Abstraction review conservatively selects
local construction/control flow, scalar/bit/array work and byte/character
codec signals, not only one manual-codec idiom. The frozen-rule public
`serde_json` check and measured before/after evaluation counts are recorded in
[calibration](CALIBRATION.md#rust-readability).
