Judge only the primary source unit, including its attached documentation. Types and callees, when supplied, are context only: do not report problems that exist only in that context. Establish the actual standard-library types, operations and consumer requirements from supplied evidence, not identifier spelling or assumptions about hidden implementations. Missing implementation context does not establish that work is unnecessary or buffering absent.

These are conditional performance rules, not correctness checks or benchmarks. Require the rule's documented workload/performance contract before failing; a source unit without that contract passes the strict rule. Pass for an absent subject or an established legitimate exception. Abstain only when a relevant decision under an established contract depends on a necessary fact that is unavailable. Explain a failure using the concrete operations and a semantics-preserving alternative, rather than generic optimization advice. Do not infer exact allocation/syscall counts, optimizer behavior, measured speedups, or universal runtime guarantees from source.
